# NOC MCP curated read tools + surface pruning — design

- **Date:** 2026-09-01
- **Service:** `services/mcp/noc`
- **Baseline:** commit `f5f277c`, VERSION `0.12.2`
- **Status:** approved, pending implementation plan

---

## 1. Problem

The `noc` MCP server registers **169 tools** — 16 hand-written plus ~153 auto-generated by
`FastMCP.from_openapi()` from the bundled spec. LibreChat reports 245 tools across all 9 servers.

Two consequences, both measured against the spec and the on-charger catalog:

1. **Generated names are unusable.** They are machine-derived from operationId and truncated at a
   hard 56 characters, mid-word. 34 names sit exactly at that cliff
   (`error_trends_by_client_api_v1_stats_error_trends_by_clie`). No two collide today; nothing
   prevents it. ~27 of them expose user administration no NOC engineer will ever ask for.

2. **The bloat is hiding the platform's best capabilities.** An earlier audit concluded Manthan had
   no incident correlation, fleet triage, time-series, session-failure analysis or SLA rollups.
   That was wrong. All of it already exists as backend endpoints and is already registered — under
   names nobody can find. `/reports/session-failures`, `/reports/ticket-resolution`,
   `/reports/fault-frequency`, `/chargers?offline_only`, `/chargers/{id}/sessions/{sid}/events`,
   `/chargers/{id}/telemetry/aggregated`.

3. **The offline asymmetry.** All 14 hand-written `charger_*` tools proxy to the live device and
   carry "charger must be ONLINE". The NOC backend's `/history/*`, `/telemetry/*` and
   `/ocpp-config/cache` endpoints read TimescaleDB and answer *after* a charger drops. When a
   charger goes dark the agent loses its best instruments and does not reach for the archive that
   still works.

**Surface totals** — NOC backend 282 operations across 37 modules (153 GET / 129 write);
on-charger catalog 239 rows across 7 services (124 GET / 115 write). 521 endpoints total.

---

## 2. Scope

**In scope (read-only throughout):**

- 8 curated tools over endpoints that already exist and already work.
- Route-map pruning of the generated set, including everything the curated tools replace.
- Catalog loader extended to describe all 239 on-charger endpoints with their required role.
- Labeled `source` / `as_of` envelope on new tools, plus live→history fallback in 3 existing tools.

**Explicitly out of scope:**

- Any write path. `ReadOnlyProxyMiddleware` and the GET-only route map are untouched. No new
  capability to mutate a charger is introduced. The on-charger control tier is a separate spec.
- `UnlockConnector`, `ChangeAvailability`, `TriggerMessage` — absent from both surfaces
  (zero matches for "unlock"/"lock" across all 239 catalog rows). These are firmware/CMS feature
  requests, not integration work.
- The OpenAPI drift CI check (finding S2) and per-tool telemetry (S3) — separate, smaller changes.

## 3. Architecture

`server.py` stays a thin builder. Each new concern gets its own module exposing a
`_register_*_tools(mcp, client)` function, matching the convention already established by
`control_center.py` and `ssh_exec.py`.

```
noc_mcp/
  server.py          thin builder; route maps; middleware wiring
  catalog.py         NEW  - moved out of server.py, extended to all 239 rows + roles
  reports.py         NEW  - noc_report / noc_stats dispatchers
  fleet.py           NEW  - noc_fleet_status
  history.py         NEW  - per-charger composites + fallback helper
  control_center.py  MODIFIED - fallback in 3 tools
  readonly.py        UNCHANGED
  ssh_exec.py        UNCHANGED
  auth.py, config.py UNCHANGED
```

`_load_control_center_catalog()` moves out of `server.py` into `catalog.py`. It is 45 of
`server.py`'s 125 lines and does not belong in the builder.

**Rationale for separate modules over one `curated.py`:** the two data sources — live device via
proxy, versus NOC backend TimescaleDB — must stay visibly separate, because the entire fallback
design depends on knowing which is which. Merging them into one file blurs exactly the distinction
the design rests on.

## 4. The 8 new tools

Reports and stats use a **dispatcher** shape: one tool with the endpoint name as a described enum.
This covers 24 endpoints in 2 tools, mirroring the catalog+proxy pattern already proven in this
codebase, and keeps net tool count falling rather than rising.

| Tool | Module | Covers |
|---|---|---|
| `noc_report(report, **filters)` | `reports.py` | all 13 `/api/v1/reports/*` |
| `noc_stats(metric, **filters)` | `reports.py` | all 11 `/api/v1/stats/*` |
| `noc_fleet_status(...)` | `fleet.py` | `/chargers` (`offline_only`, `online_only`, `search`, `customer_name`, `model`) + `/chargers/map` |
| `noc_charger_history(charger_id, limit)` | `history.py` | `/history/sessions` + `/history/alarms` |
| `noc_charger_telemetry(charger_id, ...)` | `history.py` | `/telemetry/latest` + `/telemetry/aggregated` + `/telemetry/history` |
| `noc_session_events(charger_id, session_id)` | `history.py` | `/sessions/{sid}/events` |
| `noc_charger_stability(charger_id)` | `history.py` | `/stability` + `/commands` + `/ssh-status` |
| `noc_charger_ocpp_config(charger_id)` | `history.py` | live `:8003 config/ocpp` with `/ocpp-config/cache` fallback |

Dispatcher enums carry a one-line description per value, so the model sees every available report
in a single tool description rather than having to find 24 separate tools.

## 5. Pruning

Two categories of exclusion, added to `_ROUTE_MAPS` **before** the catch-all `GET → TOOL` map:

1. **Irrelevant to NOC work** — `/api/v1/auth`, `/api/v1/admin`, `/api/v1/roles`,
   `/api/v1/permissions`, `/api/v1/teams`. 27 generated GET tools.

2. **Replaced by a curated tool** — `/api/v1/reports`, `/api/v1/stats`, and the specific charger
   sub-paths the composites now own (`/history/*`, `/telemetry/*`, `/sessions/*`, `/stability`,
   `/ocpp-config/cache`, `/commands`, `/ssh-status`). ~34 generated tools.

Category 2 is not optional. Leaving a generated tool in place alongside a curated tool that does
the same job is worse for selection than either alone — the model sees two routes to one answer and
has no basis to choose. **Every endpoint a curated tool covers is excluded from the generated set.**

Expected net: **169 → ~116 tools** on `noc`, and a materially better surface.

The `/chargers/{id}/proxy/...` path-based proxy stays registered — the ~110-endpoint on-charger
long tail is reached through it, guarded by `ReadOnlyProxyMiddleware`.

## 6. Freshness envelope and fallback

Every new tool stamps its response so the agent never has to infer freshness:

```json
{
  "source": "live" | "history",
  "as_of": "2026-09-01T06:12:44Z",
  "stale_seconds": 9480,
  "reason": "charger offline; served from TimescaleDB",
  "...": "payload"
}
```

`reason` is `null` when `source == "live"`; `stale_seconds` is `0`.

**Which tools actually fall back.** Most of the new tools read the NOC backend's TimescaleDB rather
than the device, so they work when a charger is offline *by construction* and are always
`source: "history"` with a real `as_of`. Only `noc_charger_ocpp_config` performs a live→cache
fallback among the new tools.

**Three existing tools gain fallback** (`control_center.py`). This is the half of the offline
asymmetry that new tools alone do not fix: without it the model must know to switch tools mid
investigation, which is today's failure mode.

| Existing tool | Live source | Fallback |
|---|---|---|
| `charger_get_ocpp_status` | `:8003 api/v1/config/ocpp` | `/api/v1/chargers/{id}/ocpp-config/cache` |
| `charger_get_alarms` | `:8006 error-generator/*` | `/api/v1/chargers/{id}/history/alarms` |
| `charger_get_session_details` | `:8003 api/v1/session_details/*` | `/api/v1/chargers/{id}/history/sessions` |

Fallback fires **only after the live call fails**. The happy path is byte-identical to today apart
from the added envelope keys, so existing behaviour is preserved.

## 7. Catalog change

`_load_control_center_catalog()` currently filters `Method == GET`, so the catalog describes 124
endpoints and silently omits 115 — the entire on-device control surface.

Drop the filter. The catalog gains a `method` and `required_role` field per row and describes all
239. The agent can then say "this charger supports a SECC reset, which needs admin" without being
able to fire it.

**The proxy stays GET-locked.** `ReadOnlyProxyMiddleware` is unchanged, and `how_to_call` keeps its
explicit "Read-only (GET) endpoints only" instruction. Non-GET rows are marked
`"callable": false` with a short reason, so the description cannot be misread as an invitation.

This is knowledge, not reach — and it is what makes the future control-tier spec reviewable.

---

## 8. Error handling

Follows the existing `_proxy_get` contract: never raise, return a structured
`{"error", "port", "path"}` so composites degrade to partial results rather than failing whole.

- `/ocpp-config/cache` returns **404 with `code=NO_CACHE`** when no cache row exists. This is a
  normal "not cached yet" signal, not a failure — map it to a clean empty result with
  `source: "history"`, `as_of: null`, and an explanatory `reason`. Do not surface it as an error.
- Unknown dispatcher values return the valid enum list, not a stack trace.
- Live-and-fallback both failing returns a structured error naming both attempts.

## 9. Testing

TDD — tests written before implementation. Extends the 53 tests currently passing in
`services/mcp/noc/tests/`, reusing `fake_noc.py`.

| Area | Cases |
|---|---|
| Dispatchers | valid name routes to the right path; unknown name returns the enum; filters pass through; every enum value maps to a real spec path |
| Envelope | live success → `source=live`, `stale_seconds=0`, `reason=null` |
| Fallback | live fails → `source=history` with `as_of` + `stale_seconds`; both fail → structured error naming both |
| `NO_CACHE` | 404 `code=NO_CACHE` → clean empty result, not an error |
| Route maps | each excluded prefix registers **zero** tools; a sampled kept path still registers |
| No duplicates | no curated tool and generated tool cover the same path |
| Catalog | all 239 rows present; roles included; non-GET rows marked `callable: false` |
| **Safety invariant** | no registered tool can issue a non-GET; `method=POST` on the proxy still raises `ToolError` |
| Regression | all 53 existing tests pass unchanged |

The safety invariant test is the important one: it must fail loudly if any future change lets a
write reach a charger through this server.

## 12. Assumptions

1. **The bundled spec matches production.** Everything is read from `noc_openapi.json` at `f5f277c`.
   If the backend has moved, module counts move with it — which is the drift risk in S2.
2. **`rbac-rules.csv` is complete and current**, and its `Required Role` column reflects what the
   devices actually enforce. Only descriptive in this spec, so a wrong role is a documentation bug
   rather than a security one — but it must be verified before any control tier is built on it.
3. **Not every charger exposes every endpoint.** The catalog is a union across models and firmware;
   tools must degrade cleanly on 404, as `_proxy_get` already does.
4. **`/telemetry/*` and `/history/*` read TimescaleDB, not the device**, and therefore answer for an
   offline charger. This is the premise of section 6; if any of them proxies to the device, that
   tool loses its offline guarantee and must be re-classified.
5. **Read-only remains a product guarantee.** Nothing here introduces a write.
